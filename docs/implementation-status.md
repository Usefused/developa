# Connected explorer and intelligence implementation

Verified on 26 August 2026. This record covers the server, Git tracker, persisted Go index, call chains, context and intelligence APIs, and embedded browser UI. The architecture describes a broader product; [explorer-api.md](explorer-api.md) and the [generated OpenAPI contract](../api/openapi.json) document the routes actually served.

## Implemented boundaries

| Component | Location | Implemented |
| --- | --- | --- |
| Native command | `cmd/denverr`, `internal/server` | Serve, scan, workspace registration, version metadata, migrations, tracker lifecycle, signals, graceful shutdown |
| HTTP transport | `internal/transport/http` | chi routing, health/readiness, shared-token authentication, scoped snapshots, calls/chains/context, cited Features and answers, manual scan admission, safe errors and trace IDs |
| PostgreSQL adapter | `internal/store/postgres` | Versioned migrations, immutable publications, batched file/symbol/call storage, SQL-filtered pagination/search, bounded chains, Features/answers, leased analysis jobs, durable audit/outbox rows |

| Application services | `internal/application` | Serialized scans, versioned-index freshness, citation validation, background analysis worker with durable page checkpoints/retries, snapshot-pinned answers, and explicit batched function/callee reviews with per-function cache reuse |
| Model adapter | `internal/model/ollama` | Local inference by default; explicit authenticated Ollama Cloud mode; model revision verification, bounded JSON validation, concurrency/deadline limits and trace propagation |
| Browser UI | `internal/webui` | Embedded file blocks, source details/code viewer, Calls/Used by chains, React Flow application/feature views, saved cited Features, explicit function/callee reviews and parameter notes, background job status, snapshot notices and responsive themes |
| Standalone scan | `cmd/denverr` | One-shot JSON scan and newline-delimited watch reports; no database requirement |
| Telemetry | `internal/telemetry` | stderr or explicit OTLP HTTP export, a standard SDK disable switch, W3C trace propagation and sanitized errors |
| Packaging | `.goreleaser.yaml`, `.github/workflows/release.yml`, `install.sh` | Native macOS, Linux and Windows archives with embedded UI, checksums, an installer and main-driven GitHub releases |

The parser/source packages do not depend on HTTP or persistence. Both CLI and server use the application scan pipeline. One server manages up to 32 workspaces, with PostgreSQL registrations restored after restart. Clients can select relative folders within operator-allowed roots, but cannot submit arbitrary roots, commands or actor identities. A shared token identifies an operator, not an individual user.

## Data and update guarantees

- Reads stay pinned to an explicit publication. The UI announces a newer snapshot without replacing an open declaration until the user selects **Show latest**.
- A scan publishes files, symbols, current pointer, audit outcome and outbox event in one transaction. Failed publication leaves the previous data and comparison baseline intact.
- Calls are persisted with the same publication. A schema-level index version forces reindexing when unchanged source needs newer analysis. Resolution uses captured local-module source; it never downloads or executes repository dependencies.
- Same-execution retries are idempotent. A new execution restoring previously seen content receives a new publication identity and preserves its new change evidence.
- File and symbol pages filter, count, sort and paginate in PostgreSQL, including searches for symbols contained in files. Each page uses one SQL statement; writes use batches rather than one statement per symbol.
- Chain reads use one bounded SQL traversal and prioritize discovery edges so node/edge caps do not disconnect returned nodes. Dynamic calls and unavailable external targets remain unresolved. Context retrieval is SQL full-text search, not semantic/vector search.
- The [flow API](flow-api.md) returns bounded application, symbol, and feature graphs with canonical source, root classifications, full-snapshot dependency counts, visible neighbor IDs, and cycle groups. It uses one SQL statement regardless of seed/file count; graph annotations operate only on that bounded result. Clients can recenter or page through call sites in separate small requests. React Flow only lays out those facts. Explanations are explicit cached answer requests with topology-aware provenance, not automatic analysis.
- Feature generations and answers persist canonical citations, snapshot identity and model provenance. Local weights digests and cloud provider revisions remain distinct. Continuations copy earlier features into a new immutable generation and advance a coverage cursor. Stale parents, changed model revisions, invalid citations and failed persistence cannot replace prior results. Features are always labeled inferred; partial coverage and truncated source remain visible.
- Features reads expose an optional same-repository `saved_snapshot` navigation hint when the requested source has no analysis. The UI follows it on Features navigation, visibly pins that source, and leaves explicit snapshot selections unchanged. SSE updates progress only; saved cards stay mounted until the user refreshes or navigates. Discovery remains one SQL statement with a partial index over analyzed snapshots; evidence never crosses source boundaries.
- Feature discovery is explicit by default; optional automatic analysis is admitted transactionally only for clean, complete Git commits, with durable per-commit deduplication. Working-tree edits update the structural index without automatic inference. A PostgreSQL queue separates model work from HTTP lifetimes; the worker checks leases before feature publication, saves one page per checkpoint, retries bounded failures and resumes persisted progress after restart. No NATS or Redis is required for this first queue. A dedicated feature model can be stronger than the separate review and answer models. The UI reads saved results/progress and renders an agent-ready feature brief before the graph; feature generation POSTs return 202 admission.
- Background analysis and answers have separate model settings and execution gates. File-bounded inference pages reuse a PostgreSQL cache keyed by repository, exact source facts, verified model revision, prompt/schema and inference policy. Focused function/feature explanation buttons reuse the answer API and validated answer cache. Cached evidence is revalidated against current canonical positions. Published runs expose cache-hit and model-call counts, not a billing meter.
- User-triggered model executions have durable admission/outcome audits and OTEL correlation. Prompts, questions and source are excluded from telemetry. Model inputs are untrusted data and cannot invoke tools. There is no automatic model download or cloud fallback.
- Polling compares the current eligible working tree, including uncommitted edits. It does not capture every intermediate edit. The first capture after startup has no prior in-process manifest and exposes `changes_known: false`.
- Source text is inserted into the browser as text under a restrictive Content Security Policy. Verified API tokens persist in localStorage until logout/401; editor-root and theme preferences are also saved locally. Editor links map repository-relative positions onto the user's own checkout.

## Limits and remaining work

- Static type-assisted resolution covers unconditional, non-platform, non-test source within a captured local module, using explicit gc/amd64 type sizes. There is no complete build-variant selection, workspace/replacement resolution, external dependency loading, dynamic-dispatch analysis, general reference traversal, or move-stable identity. Diagnostics and unresolved edges expose these limits.
- Flows are bounded static call graphs, not runtime execution order or branch/control-flow reconstruction. Candidate roots are not proven handlers. Traversal includes seed ancestry and seed descendants, not unrelated sibling branches; disconnected components and unresolved links can remain absent. Source budget limits can make a flow explanation smaller than the displayed graph, and this is disclosed.
- No local Ollama model is installed on the verification host. Cloud smoke tests used the operator's explicitly authorized API key without displaying or committing it. No model was downloaded. Cloud source transfer is disclosed and uses only the configured provider; local inference quality remains unverified.
- The later multi-model cloud fixture smoke test was blocked by the permission guard and was not run. New queue/cache/model-role delivery checks use deterministic local protocol fixtures; they do not establish the relative quality of the selected cloud models.
- SSE delivers stored job state and completed validated answers, not provider tokens. There is no durable SSE event replay log; reconnect reads current state. Background jobs survive browser disconnects, while answer requests are canceled on disconnect.
- Features analyze bounded batches with resumable coverage; cross-batch synthesis/deduplication is not implemented. Context search is lexical. Free-form questions are API-only; focused explanation buttons use the same API. There is no chat composer, answer-history read endpoint or MCP interface.
- Automatic AI observes clean commits through the checkout poller, so intermediate commits or immediately dirtied checkouts may be missed. There is no Git-object backfill yet. A manually requested rebuild can reuse cached inference; within-file page shifts can still cause additional calls. No hard token/spend quota or provider billing integration is implemented.
- No selected Go dependency graph or release-version inference. Captured imports, Git revision and tags are evidence for later extraction, not a complete dependency/version model.
- No clone/fetch, multi-tenant authorization, distributed source-tracker lease, snapshot retention policy, or outbox dispatcher. The structural scan queue is process-local; AI jobs use durable leases. Outbox insertion does not mean external delivery. PostgreSQL is the queue for this version; there is no NATS integration or standalone worker executable.
- No native filesystem notifications, package-level incremental analysis, frozen filesystem snapshots, hostile-repository worker isolation, or submodule recursion. Run one engine process per workspace group; multiple repositories share that engine.
- No production load/security certification. TLS-offloading proxies need an explicit trusted-origin/proxy design before deployment beyond the documented direct loopback setup.

## Denverr native release conversion

The user-facing product, executable, UI, API title, browser storage and telemetry service names are now Denverr. Existing `developa_*` PostgreSQL tables remain unchanged so saved indexes upgrade without a destructive data migration. The browser migrates the old credential and preferences keys once. The unified `denverr` command provides `serve`, `scan`, `workspace add`, and `version`; first-run serve generates a private operator credential when one is not supplied.

The container runtime files were removed. GoReleaser v2.18.0 validates `.goreleaser.yaml` and a snapshot build produced six successful archives: macOS, Linux and Windows on AMD64 and ARM64, plus checksums. The generated macOS ARM64 binary reported its injected version, commit and build date; both tar and zip contents were inspected. Every push to `main` runs a serialized release workflow that creates the next patch `v*` tag and publishes it as a GitHub release. The release also includes a tested macOS/Linux installer that selects the native archive and verifies its checksum before replacing the installed executable. The workflow performs tagging and publishing in one run because tags pushed with `GITHUB_TOKEN` do not start another workflow. Checkout, Go, Node and GoReleaser actions are pinned by commit.

For this conversion, the full non-race Go suite passed, including local-listener tests outside the restricted sandbox. Vet, gocyclo ≤10, OpenAPI generation/validation, frontend lint, 104 JavaScript tests, 24 React tests, embedded-asset freshness, the native build and command help/version smoke tests passed. No model inference was invoked.
